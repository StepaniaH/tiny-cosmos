## 执行顺序

### P0：流程正确性

1. 序章切换时序与响应速度。
2. 序章结束后自动展开第一项场景引导。
3. 页面切到后台后的确定性进度补算。
4. 同一任务内部进入新操作阶段时，重新出现一次引导。
5. “结构开始保护内部”阶段提示可以收起。

### P1：可读性与解释

6. 画布轨道与特殊线条的悬浮说明，并连到档案。
7. 分子阶段以后扩展、固定左侧物质框，限制在可视区内并独立滚动。
8. 放大“反宇宙接触”全部正文、指标和方案说明。
9. 第一次出现“反侧压力”时明确解释，不依赖玩家主动翻档案。
10. 修正三栏独立增长造成的视觉失衡与大块空白。

### P2：内容节奏

11. 给关键档案增加情境入口和引导。
12. 增加第一轮后期的可选互动密度，但不以强迫点击替代等待。
13. 设计等待期的长期主动层；本轮只确定原则，不直接加入重型 SLG。

## 问题清单

### UX-01 序章先换画面、后出现转场

状态：已验证

现象：点击“下一幕”后，新图和新文案立即出现，约一百毫秒后扫屏转场才变得可见，视觉上像转场迟到。

根因：`js/prologue.js` 的 `go()` 先调用 `playTransition()`，但随后在同一个调用栈立即替换图片和文案；转场动画从透明状态开始，因此第一帧露出了新内容。

方案：

- 把转场改成“旧画面 → 遮罩进入 → 遮罩覆盖时换帧 → 遮罩离开”。
- 总时长收紧到约 0.5 秒，换帧点约 0.2 秒。
- 转场期间锁住上一幕、下一幕和圆点，避免连续点击造成乱序。
- 打开序章时预载当前序章图片，减少换帧点出现占位图的概率。

验收：

- 点击后第一可见反馈是转场，而不是新一幕。
- 新图和新文案只在遮罩覆盖后出现。
- 连续快速点击不会跳两幕、倒退或留下永久遮罩。
- 减少动态效果时仍然立即换帧，不额外等待。

### UX-02 序章结束后第一项引导默认收起

状态：已验证

现象：看完或跳过序章后，顶部只显示“打开引导”，玩家还要再点击一次。

根因：`js/ui.js` 把 `guideCollapsed` 初始化为 `true`，序章关闭事件只刷新界面，没有改变该值。

方案：

- 正常游戏默认展开引导。
- 序章关闭时显式展开当前引导。
- 自动化 fixture 仍默认收起，避免测试遮罩挡住被测控件。

验收：首次进入、完整看完、跳过序章三种路径都会直接看到第一项场景引导。

### UX-03 切到其他标签页或应用后放置进度停止

状态：已验证

现象：`document.hidden` 时引擎被主动停止，返回后从原状态继续，隐藏期间没有生产、研究、任务稳定计时或接触进度。

根因：`js/main.js` 的 `visibilitychange` 处理在隐藏时执行 `GameEngine.stop()`，恢复时只重新 `start()`；浏览器后台限频也没有墙钟补偿。

方案：

- 保存时同时记录墙钟时间。
- 隐藏或页面关闭前保存；恢复或重新载入时按墙钟差补算。
- 引擎支持以较大但有上限的时间片重放生产、代谢、研究和场景状态。
- 补算不替玩家做选择；遇到决策门时只继续资源链，不越过决策。
- 设 12 小时单次补算上限，避免错误系统时间造成冻结；界面说明实际补算时长。
- 序章与重生图像记录仍视为暂停，不把阅读时间计入生产。

验收：

- 切后台 5 秒后返回，资源和 `elapsedSeconds` 均前进约 5 秒。
- 稳态、准备、敌人止损和自由观测使用同一时间基准。
- 重载页面也能补算上次保存后的进度。
- 补算不会自动选择法则、接触方案、反侧回应或文明裁定。

### UX-04 手动隐藏后，同一任务的新阶段不再自动引导

状态：已验证

现象：任务编号变化时引导会重开，但同一任务中的目标从等待变为可研究、从研究变为合成、从合成变为建立单元，或从反侧回应恢复到建设时，仍保持收起。

根因：当前自动重开只比较 `missionStep`，没有比较任务内部的操作阶段。

需要覆盖的阶段变化：

- 核子任务：补库存 → 购买生产单元 → 聚焦。
- 各研究任务：等待 RP → 研究按钮可用 → 合成目标 → 生产单元目标。
- 反侧任务：回应客体 → 返回物质建设。
- 接触准备：选择准备 → 执行对应资源条件。
- 接触处理：选择方案 → 执行该方案。
- 第二轮的原子、分子、谱系跃迁中的多段目标。

方案：生成稳定的 `guidePhaseKey`，由任务编号、当前聚光目标和关键子状态组成。玩家的“稍后再看”只压住当前 phase；phase 改变时自动出现一次。

验收：

- 上述每个阶段转换都会自动出现一次。
- 同一 phase 内资源数值波动不会反复弹出。
- 玩家再次收起后，在 phase 未改变前不打扰。

### UX-05 档案缺少情境引导

状态：已验证

方案：

- 场景引导在研究通道、第一法则、反侧压力、细胞、生命和文明首次出现时显示“查看相关档案”。
- 资源卡影响标签、反侧压力说明和画布线条都能直接打开对应档案条目。
- 打开的档案直接定位并展开目标条目，不让玩家再搜索一次。

验收：玩家不必离开当前语境猜“档案里应该搜什么”。

### UX-06 画布线条含义不明

状态：已验证

现象：画布同时存在物质层轨道、未揭示虚线、焦点强调、保护弧、坐标线和反侧压力弧，但没有就地说明。

方案：

- 鼠标靠近轨道或特殊弧线时显示小型检查窗。
- 说明“这是什么”“是否参与结算”“当前状态”。
- 检查窗提供“查看相关档案”。
- 第一版覆盖物质轨道、未揭示轨道、焦点、保护线、坐标线、反侧压力；反侧客体几何以后补充。

验收：

- 不移动画布元素，不妨碍点击中央光核。
- 鼠标与键盘都能进入档案入口。
- 手机没有悬浮能力时不显示空检查窗，核心说明仍可从引导和档案访问。

### UX-07 分子出现后左侧物质框不够长

状态：已验证

根因：物质框只有 `max-height`，内容少时按内容高度收缩；整页向下滚动时左栏也会离开，造成中后期大块空白。

方案：

- 分子任务开始后，物质框固定为“视口剩余高度”，但不超过屏幕。
- 标题固定，卡片区域独立滚动。
- 未揭示层提示贴近框底，已出现层级增多后自然转为滚动。
- 小屏回到普通文档流，不套双重滚动。

验收：

- 1280×720 下框体不越出屏幕。
- 中后期滚到接触面板时，左侧物质框仍在并可滚动。
- 390×844 下不出现内外两个难以控制的竖向滚动区。

### UX-08 “反宇宙接触”字体仍然过小

状态：已验证

范围：

- 威胁名称、目标、速率和止损数据。
- 方案标题、方案正文、收益/成本标签。
- 反侧压力说明。
- 客体图鉴标题、状态和正文。

验收：

- 默认文字不低于约 11px；主要标题 14–16px。
- 1280px 宽下无需放大页面即可阅读。
- 放大字体设置仍不溢出方案卡。

### UX-09 等待期缺少主动层

状态：设计保留

判断：需要优化，但不应该加入“每隔几秒点垃圾”的伪忙碌。随机碎片如果只给奖励，会把叙事游戏变成注意力税；如果错过就损失，更会破坏放置承诺。

建议采用三层结构：

1. **被动层**：资源、研究和计时继续运行，玩家离开不会受罚。
2. **可选主动层**：30–90 秒出现一次可忽略的观测事件；处理后提供一段遗产句子、路线证据或短期调度机会，错过只进入档案，不扣收益。
3. **建设层**：后期加入少量“宇宙机构”而非通用城建，例如边界站、谱系库、回流温室、观测议会。建筑改变后续事件和叙事证据，不只是 `+10%`。

碎片点击可以作为原型，但必须满足：

- 不要求持续盯屏。
- 不连续刷出。
- 不因错过造成 FOMO。
- 奖励以新信息和决策上下文为主，数值只作补偿。

### UX-10 第一轮没有及时解释反侧压力

状态：已验证

现有档案已有“反侧压力”条目，但首次出现处没有强制解释。

首次说明统一为：

> 反侧压力不是生命值，也不会直接导致失败。它表示另一侧对你重复方法的预测程度，会轻微压低原子及以上生产。沿用主路线会让文明提案更明确但压力上升；转向会打乱预测但稀释路线信号。

圆回设定的方式：第一轮早期不提前命名是合理的，因为真空水蛭阶段只能观测到“截流”；在反相晶簇出现后，观测核才有足够样本发现另一侧预测的是方法而非单一资源。这个揭示必须在分子任务引导中明确说出，不能只靠玩家自行推理。

验收：进入分子阶段时自动看到简述，并能一键打开完整档案。

### UX-11 第一轮后期内容密度不足

状态：设计保留

问题不只是总时长，而是“有意义的状态变化”频率过低。现有偶发发现可能被第一条未读卡堵住，后续内容排队但玩家感觉不到。

短期方案：

- 未处理发现不阻塞后续信号计时；在卡片上显示“还有 N 条待整理”。
- 文明研究长等待增加 2–3 个低频、可忽略的文明前信号。
- 至少一个事件要求玩家解释证据，另一个要求短期调度；不要全部是纯文本。
- 每 60–90 秒至少发生一次可见状态变化，但玩家离开时自动归档，不损失资源。

长期方案：把后期节奏从“等 RP”改成“建设证据 → 解释冲突 → 让文明引用这些记录”，RP 只作为自然时间门，不再是唯一目标。

### UX-12 “结构开始保护内部”提示无法关闭

状态：已验证

根因：`#era-indicator` 被设计成永久、`pointer-events: none` 的状态覆盖层。

方案：

- 增加“收起”按钮并把选择存入当前轮状态。
- 收起后，反侧压力仍在资源卡和接触面板显示。
- 新一轮重新出现一次。

验收：按钮可点、重载后保持收起、下一轮会重置。

### UX-13 三栏出现大块/小块和空白失衡

状态：待验证

已复现的主要原因：

- 三栏使用 `align-items: start` 独立增长。
- 左侧物质框会随整页滚走，接触与路线内容变长后左侧形成整块空白。
- 渐进显示会让早期各栏高度差异很大。

本轮修正：

- 分子阶段后固定左侧物质框并使用内部滚动。
- 统一关键面板标题高度、正文最小字号与卡片间距。
- 保持中间接触内容和右侧路线内容是正常文档流，不强行把不同信息量拉成同高卡片。

待原图确认：如果“大一块小一块”指某一组具体选项卡，而不是三栏纵向失衡，需要按截图再做定点修复。

## 独立游戏化方向

### 是否值得以后用 Godot、Unity 或 Unreal 重构

值得把它做成独立游戏，但现在不建议立即换引擎。先用网页版本完成第一轮、第二轮和一个终局工程原型，证明三件事：

1. 玩家愿意读并记住跨轮因果。
2. 等待之外有足够多的解释、建设和取舍。
3. 四条路线能产生真正不同的中后期玩法，而不只是文案与倍率不同。

只有这三点成立，换引擎才是在放大作品；否则只是在更昂贵的技术栈里继续修核心循环。

引擎倾向：

- **Godot 4**：当前最合适。2D/UI、叙事、数据驱动系统足够，包体和研发负担较低，也方便以后加入轻量粒子、节点图和建设界面。
- **Unity**：如果以后需要成熟的商业插件、控制台移植资源或扩充团队，可选；代价是项目与工具链更重。
- **Unreal**：除非明确转向强 3D 宇宙奇观和电影化演出，否则对当前以 UI、文本和系统叙事为核心的作品过重。

### 从放置网页游戏转成买断制叙事系统游戏

建议核心从“等数值”改为：

> 观测 → 干预 → 解释 → 建设 → 留档 → 跨轮反证

放置只承担时间质感和资源自然生长，不承担主要乐趣。SLG/建设可以加入，但建筑必须是世界观中的制度与关系，例如：

- 边界航站决定谁能穿过视界。
- 谱系库决定哪些差异可以被继承。
- 回流温室决定短缺由哪一侧承担。
- 观测议会决定证据如何公开、谁有权反驳。

这些建设应改变事件池、文明台词、反侧回应和结局条件；如果只是增加产量，会重新滑回普通放置游戏。

商业上更适合先做可保存的免费试玩版，再做无广告买断制完整版。当前气质、长线主题和档案系统都比 IAA 更适合 Steam 受众。

## 四轮档案与大结局

第二轮看不到第一轮完整档案是合理的，但不能真的把历史从元存档删除。建议分成两层：

- **当前轮可读档案**：只保留本轮观测核能够直接访问的内容。
- **跨轮沉睡档案**：保存每轮的真理、异议、未解问题、文明证词和反侧样本，但界面只显示不可读轮廓。

建议元数据：

```text
loopArchiveSummaries[]
provenTruths[]
civilizationWitnesses[]
recordedDissent[]
unresolvedQuestions[]
reverseSamples[]
archiveWakeProgress
```

第四轮终局不是简单“恢复全部文本”，而是让四座文明、反侧后来者和观测核分别提供解码权。大结局可以分三步：

1. 四轮档案翼依次苏醒，每一翼同时显示当轮结论与后来轮次对它的反驳。
2. 玩家决定完整历史由观测核保管、由文明共同保管，还是写入下一次宇宙的公共初始条件。
3. 最终画面让四轮档案同时可读，但不把矛盾合并成唯一真相；“全部苏醒”代表历史获得共同访问权，而不是所有人终于意见一致。

这样既保留每轮失忆的叙事合理性，也让玩家相信早期档案没有白读、早期选择没有被系统偷偷丢弃。
