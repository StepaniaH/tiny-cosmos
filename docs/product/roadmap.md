# Tiny Cosmos 制作路线图

状态：canonical
更新日期：2026-07-26
用途：维护当前制作顺序与每个阶段的可验收边界。
上位文档：[产品愿景](./vision.md)、[五轮主叙事](../design/narrative/five-loop-arc.md)

## 当前可玩边界

- 第一轮：资源链、法则、第一次接触、生命与第一座文明已经可玩。
- 第二轮：继承偏差、路线反例、后来者证词与真理裁定已经可玩。
- 第三、第四轮：已有叙事基线，尚未开放生产入口。
- 第五轮：已确定为较短的档案重建与身份揭示，尚未实现。

当前公开上限保持在第二轮。第三轮任务图、状态和结算未完整存在前，不以占位按钮或回落任务假装可玩。

## 已完成：前期体验修订

- 长期目标、当前动作、下一解锁与等待期建议集中到目标栏。
- 第一处天赋点约在 6 秒后出现；四项局内天赋各两级。
- 主动观测提供稳态校准、聚焦脉冲和回声解码，在线与离线均可充能。
- 观测与干预拆成两个工作区，并提高默认与“大字号”模式的关键信息尺寸。
- 第一轮高频任务中文改成动作与数字优先；身份和另一侧来源不再被操作文案提前说死。
- 产品愿景、世界观圣经和五轮主叙事成为文档权威入口。

## 下一切片：第二轮终结封存

目标：让第二轮真正以“局部答案成立，但宇宙仍然终结”收束，并生成第五轮可可靠重建的记录。

### 玩家可见

第二轮报告后增加三幕短结算：

1. 本轮裁定在公开条件下成立。
2. 终结仍然发生，不归咎于选错、背叛或隐藏资源。
3. 两侧报告出现相同校验和与相反资源方向，留下问题：“谁有资格把残留称为历史？”

封存后停止实时与离线增长，只允许阅读本轮和跨轮档案。界面不显示“第三轮开发中”。

### 数据边界

- 明确区分 `completedLoopNumber` 与 `nextLoopNumber`。
- 第二轮记录保存继承校准、碎片处理、路线反例、文明证词与真理裁定。
- 轮次封存必须幂等，重复操作不能追加重复签名。
- 旧签名迁移后仍能被第二轮读取。
- 公开可玩上限作为单一常量维护，封存第二轮不能误入尚未实现的第三轮。

### 验收

- 第二轮完整模拟后生成一份且仅一份终结记录。
- 保存重载后仍为已封存状态。
- 封存后推进 60 秒，资源、研究和任务时钟不再变化。
- 第一轮旧存档与 schema 1/2 签名均可迁移。
- 任何进入第三轮的请求在任务图未完成时都明确返回不可用。

## 随后：第三轮“两侧都有祖先”

只在以下内容同时具备后开放：

- 独立第三轮状态与任务图，不回落到第一轮。
- 另一侧自己的继承物、来源、约束与损失记录。
- 双方对同一事件的相反主客体档案。
- 历史公开、隔离、交换或保留异议的可操作选择。
- 本轮独立终结、跨轮签名与端到端回归。

玩家在本轮最多确认“另一侧也有连续历史与后来者”，仍不直接得知自己就是宇宙。

## 第四轮“所有条件都已满足”

- 双方公开资源、损失、终结预测与泄压责任。
- 四种终末方案各有独特操作。
- 所有条件真实成立、双方没有背叛，然后终结仍然发生。
- 结算明确保存了什么、由谁承担代价，不制造隐藏失败条件。

## 第五轮“观测者是谁”

- 15–25 分钟档案重建，不重复七层资源建设。
- 配对校验和、对齐两侧时间、重放关键决策并验证因果。
- 由前四轮证据推出 TC-07 是内部自观测功能、玩家就是当前宇宙。
- 最终只选择留下哪种记录，不提供取消终结的按钮。

## 持续验证

每个切片至少维持：

```bash
node tools/validate-static-assets.js
node tools/balance/early-agency-smoke.js
node tools/balance/first-contact-smoke.js
node tools/balance/civilization-smoke.js
node tools/balance/second-loop-smoke.js
node tools/balance/background-progress-smoke.js
node tools/balance/time-scale-smoke.js
```

新增轮次边界时再加入专用的 `round-transition-smoke.js`，覆盖封存幂等、旧存档迁移和公开轮次门禁。
