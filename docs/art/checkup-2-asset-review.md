## 模型视觉验收

### M001 观测核

报告声称已经形成“虚空、非对称环组、输出骨架”三层结构，但实际 `observation_core-perspective.png` 中最容易识别的仍是中央浅色球体和六个浅色块，暗部环组几乎消失。`m001-64-front.png` 与 `m001-64-side.png` 缩小后表现为不连贯散点，侧视图甚至无法判断这是同一个装置。

不通过原因：

- 主轮廓依赖极暗材质，预览背景和游戏背景均为深色时结构直接丢失。
- 正面与侧面剪影缺少稳定的共同识别特征。
- 中央仍是普通实体球，不符合“不可直视的中心空缺”。
- 当前实景合成只是把模型预览贴在黑色矩形中，不是上一轮要求的主项目页面合成。

下一轮门槛：先只交黑白剪影。四个视角都应由一个连续、非对称但可追踪的外轮廓构成；64px 下不允许主要信息退化成六个互不相连的小点。通过剪影后再制作材质和动画。

### M002 真空水蛭

`vacuum_leech-perspective.png` 的主要可见结构仍是粉色圆环与两段紫色杆件，所谓口器、负空间身体和拖尾之间没有形成连续受力关系。`m002-64-front.png` 与侧视图差异过大，单看缩略图无法识别它们属于同一对象。

本轮新增的 `m002-key-actions.mp4` 是有效 H.264、1280×720、30 fps、9 秒文件，但不满足动画验收：

- 约第 4 秒画面几乎完全为空，只剩不可辨认暗部。
- 第 1 秒和第 7 秒的主体状态非常接近，无法只看无声画面区分 `form / attach / siphon / retreat`。
- 没有动作名、时间段或固定参照物，无法验证附着方向和物质流向。
- 预览对象在画面中偏小，大量黑色空区掩盖了动作细节。

下一轮门槛：先交一张带原子轨道参照物的四格动作分镜，每格明确标注动作名；再交固定相机、固定曝光、无遮挡的逐帧视频。四个动作必须改变整体轮廓或空间关系，不能只靠局部旋转。

### M003 核心余像

`contact_afterimage-perspective.png` 和 64px 剪影仍以浅色完整球体为主，双壳开口只有一个很小的浅紫缺口。缩小后缺口消失，`fuel / return / archive` 三种处置无法从静态结构预判。

下一轮门槛：外壳开口至少占整体投影的 20%，内外壳之间保留可见负空间；三种处置各交首帧、峰值帧、末帧，三组峰值帧的轮廓必须明显不同。

### M004–M007

上一轮要求先提交生产、聚焦、保护、研究四类功能模型的 64×64 剪影，再决定是否继续细化。本轮只提供了 M001–M003 的剪影，因此 M004–M007 不进入复审。不要继续增加材质和动画，先完成四类功能的并排黑白剪影稿。

## VFX 验收

本轮 V004–V008 的像素内容发生变化，但仍不足以替换现有 CSS/Canvas 表现：

- `siphon-stream` 主要是水平线与噪点带，缺少来源端、目标端和速度层次。
- `overload-impact` 是重复的 T 形矩形，不能读成“回灌并压倒”。
- `cutoff-barrier` 是整幅水平色块，缺少断面形成与闭合过程。
- `observe-scan` 是重复圆点和横线，帧间变化弱，无法表达驻波采样。
- `afterimage-condense` 是圆点逐步聚合，仍与普通粒子聚拢没有区别。
- `tier-unlock` 仍是点阵方框放大，不能表现层级结构向外展开。

下一轮不要直接交完整图集，先为每个效果提交 6 帧关键帧条，并放到游戏当前观测画布的实际截图上合成。关键帧条通过后再补全 32/64 帧图集。每项同时提交正常动效和减少动态效果版本。

## 音频工程验收

本轮确实生成了 6 个音乐文件、20 个事件音、MIDI、WAV 源文件和构建脚本，这是比上一轮更完整的工程交付，但当前不能作为网页正式音频启用。

### 阻断问题

1. **清单与实际时长不一致。** `audio-catalog.json` 声称六层音乐均为 96 秒、`loopEnd = 4607999`；实际 FFprobe 结果中 `music-afterimage-coda.ogg` 为 74.109 秒，`music-observer-bed.ogg` 为 95.957 秒。
2. **循环点不真实。** 构建脚本使用 FFmpeg `-t 96`，但输入 MIDI 渲染不足 96 秒时不会自动补齐；脚本随后仍把计划时长写进清单。当前 coda 的循环终点落在文件之外。
3. **峰值超出约定。** 接触层与观测底层实测 True Peak 约 -0.5 dBFS，高于需求中的不超过 -1 dBTP。
4. **多音色写入逻辑有误。** `music-matter-pulse` 和 `music-contact-layer` 在同一 MIDI channel 的时间 0 写入多个 program change；后一个 program 会影响后续本应属于前一个音色的音符。需要使用独立 channel 或拆分后混音。
5. **事件音时长机械统一。** 20 个事件音全部为 2.5065 秒。手动点击、聚焦锁定等高频 UI 反馈不应与接触警报、余像处置采用相同尾长。
6. **清单不可移植。** `soundFont.path` 写入了构建机器的绝对 Homebrew 路径，其他环境无法按清单重建。
7. **许可不足以审计。** 许可证文件只写“Vintage Dreams permissive SF2 license”，没有许可证全文、SPDX 标识、上游 URL、版本文件或分发依据。“随 FluidSynth 安装”不能替代具体的再分发许可证明。
8. **编码描述不完整。** 文件是 Opus-in-Ogg，清单只写 `format: ogg`。运行时需要明确 codec/MIME，并提供浏览器兼容性探测或回退格式。
9. **交付文档互相矛盾。** `DELIVERY.md` 仍写“未生成 OGG 文件”和旧版本信息，而 `reports/checkup-1-followup.md` 写音频已经完成。正式包不能同时保留冲突结论。

### 下一轮音频要求

- 构建后从实际 WAV/OGG 重新读取 sample 数、时长、codec、channels 和 SHA-256，再生成 catalog；禁止从计划配置复制时长。
- 六个 stem 必须全部精确对齐同一循环 sample 数；边界做等功率交叉淡化，并提供首尾差分或自动循环测试报告。
- 使用独立 MIDI channel 表达不同音色；保存每个 channel 的 program、pan、gain 和效果参数。
- UI 点击类事件音目标 80–450 ms；发现类 0.8–2.0 秒；接触/余像类按语义单独定长，不再全部填充到 2.5 秒。
- 编码后再次进行响度和 True Peak 校验；所有音乐层叠加后的总线也必须测试。
- catalog 使用相对的 SoundFont 标识；许可证目录必须包含上游链接、原始许可文本和是否允许随游戏分发的明确结论。
- 明确提供 `codec: opus`、`mime: audio/ogg; codecs=opus`，并增加至少一种经目标浏览器验证的回退方案。
- 提供一个独立试听页面：可以单独/组合播放六层、循环 10 分钟、触发全部事件音，并显示当前文件、时间和状态。

## 自动校验需要补充的项目

当前 `validate_assets.py` 会让本轮所有内容显示为 31/31，因此下一轮必须把以下检查纳入脚本：

- catalog 时长和 loopEnd 不得超过实际音频 sample 数。
- 音频 codec、采样率、声道、峰值和响度符合清单。
- 所有源许可证路径真实存在，且不允许只写模糊的“permissive”。
- 动画预览非空帧比例、主体包围框占画面比例和动作标签存在性。
- 64px 剪影前景占比、连通区域数量和四视图一致性报告。
- VFX 每帧非空、首尾差分、透明通道与关键帧合成预览存在性。
- `DELIVERY.md`、manifest、status report 与实际文件数量保持一致。
